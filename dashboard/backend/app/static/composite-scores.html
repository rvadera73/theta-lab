Methodology (v3, 2026-10-04)

Held and watchlist names are scored together as one population, so a new candidate's rank reflects real standing against everything already held, not a separate number. Yield and conviction are each converted to a z-score (standard deviations from this population's own mean) — the standard multi-factor-fund technique — then blended 0.6 × yield_z + 0.4 × conviction_z, plus small, same-scale modifiers: +0.5 hot-trend bonus, −0.5 crash-sensitivity penalty (only when the macro stage is elevated AND the sector read is strong-confidence), −0.2 per quality flag (LOW_MOAT/THIN_MARGINS/etc. — sizing guidance, never exclusion), and −0.5 if real analyst target-price upside is below −15% (the same threshold this book's conviction formula already treats as meaningful — a check against rich yield masking a name analysts themselves think is overvalued, without double-counting that number since it's already a sub-component of conviction). The only thing that disqualifies a name outright is a tail-risk flag — GOING_CONCERN, ACCOUNTING_RISK, DELISTING_RISK, or PERMANENT_EXIT — shown separately below, since those are about capital destruction, not business quality, or a judgment call. Honest limitation: the modifier weights are a judgment call, not backtested — what changed from the prior version is that they're now scaled to be comparable to the z-scored primary signal instead of arbitrary constants that could swamp each other. The quality-flag registry is also manually curated and has had real, confirmed coverage gaps — a blank flags column means "not yet checked," not "confirmed clean." See mcp/reports/composite_score.py for the full rationale and revision history.
